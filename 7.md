## Cluster

```
═══════════════════════════════════════════════════════════════════════════
                              CLUSTER
              Несколько процессов, shared socket, один порт
═══════════════════════════════════════════════════════════════════════════

Client (TCP connection to :3000)
    │
    ▼
┌─── Socket :3000 (shared file descriptor) ──────────────────────────────┐
│                                                                         │
│   Primary Process (PID: 1000)                                          │
│   ─ НЕ обрабатывает HTTP                                              │
│   ─ Управляет lifecycle workers                                        │
│   ─ Передаёт socket fd дочерним процессам                              │
│   ─ Round-robin распределение входящих TCP connections                  │
│                                                                         │
│          ┌──────────────┬───────────────┬──────────────┐               │
│          ▼              ▼               ▼              ▼               │
│   ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐    │
│   │ Process 1   │ │ Process 2   │ │ Process 3   │ │ Process 4   │    │
│   │ PID: 1001   │ │ PID: 1002   │ │ PID: 1003   │ │ PID: 1004   │    │
│   │             │ │             │ │             │ │             │    │
│   │ V8 Isolate  │ │ V8 Isolate  │ │ V8 Isolate  │ │ V8 Isolate  │    │
│   │ Event Loop  │ │ Event Loop  │ │ Event Loop  │ │ Event Loop  │    │
│   │ Heap: 50MB  │ │ Heap: 50MB  │ │ Heap: 50MB  │ │ Heap: 50MB  │    │
│   │             │ │             │ │             │ │             │    │
│   │ Address     │ │ Address     │ │ Address     │ │ Address     │    │
│   │ Space:      │ │ Space:      │ │ Space:      │ │ Space:      │    │
│   │ ISOLATED    │ │ ISOLATED    │ │ ISOLATED    │ │ ISOLATED    │    │
│   └──────┬──────┘ └──────┬──────┘ └──────┬──────┘ └──────┬──────┘    │
│          │                │                │                │           │
│          └────── IPC (Unix socket / pipe) ─┴────────────────┘          │
│                           ▼                                            │
│                      Primary Process                                   │
│                                                                         │
│   Process 2 exit(1)? → Event 'exit' → Primary: cluster.fork()          │
│   Остальные процессы: unaffected (изоляция адресных пространств)        │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘

  Memory model:     Isolated address spaces (виртуальная память ОС)
  Communication:    IPC — serialized messages (JSON через pipe)
  Port sharing:     Primary создаёт socket fd → передаёт через fork
  Scheduling:       OS scheduler (каждый процесс — отдельная единица)
  Fault isolation:  Process crash не затрагивает другие processes
  Overhead:         ~30-50MB per process (новый V8 heap + ОС structures)
  Scalability:      1 process per CPU core (horizontal)


═══════════════════════════════════════════════════════════════════════════
                          WORKER THREADS
           Несколько потоков, shared address space, один процесс
═══════════════════════════════════════════════════════════════════════════

Client (TCP connection to :3000)
    │
    ▼
┌─── Socket :3000 (принадлежит Main Thread) ─────────────────────────────┐
│                                                                         │
│   ONE Process (PID: 2001)                                              │
│   ONE Address Space (общая виртуальная память)                          │
│                                                                         │
│   ┌─────────────────────────────────────────────────────────────────┐  │
│   │              Shared Memory Region                                 │  │
│   │                                                                  │  │
│   │  SharedArrayBuffer: [bytes...]                                   │  │
│   │  Доступен всем потокам без копирования                           │  │
│   │       ▲              ▲              ▲                            │  │
│   │       │ read/write   │ read/write   │ read/write                 │  │
│   │       │              │              │                            │  │
│   │  ┌────┴──────┐ ┌────┴──────┐ ┌────┴──────┐                     │  │
│   │  │Main Thread │ │ Thread 1  │ │ Thread 2  │                     │  │
│   │  │           │ │           │ │           │                     │  │
│   │  │ V8 Isolate│ │ V8 Isolate│ │ V8 Isolate│                     │  │
│   │  │ Event Loop│ │ Event Loop│ │ Event Loop│                     │  │
│   │  │           │ │           │ │           │                     │  │
│   │  │ socket.   │ │ НЕ слушает│ │ НЕ слушает│                     │  │
│   │  │ listen()  │ │ порт      │ │ порт      │                     │  │
│   │  │           │ │           │ │           │                     │  │
│   │  │ HTTP req  │ │ CPU work: │ │ CPU work: │                     │  │
│   │  │ handling  │ │ crypto    │ │ image     │                     │  │
│   │  │           │ │ hashing   │ │ resize    │                     │  │
│   │  └─────┬─────┘ └─────┬─────┘ └──────────┘                     │  │
│   │        │   postMessage│                                          │  │
│   │        │  (structured │                                          │  │
│   │        │   clone /    │                                          │  │
│   │        │   transfer)  │                                          │  │
│   │        └──────────────┘                                          │  │
│   │                                                                  │  │
│   └─────────────────────────────────────────────────────────────────┘  │
│                                                                         │
│   Thread 1 uncaught exception? → ВЕСЬ процесс (PID 2001) под угрозой   │
│   Нет изоляции адресных пространств — общая memory corruption          │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘

  Memory model:     Shared address space (один процесс)
  Communication:    postMessage (structured clone) ИЛИ SharedArrayBuffer
  Port:             Только Main Thread владеет socket
  Scheduling:       OS scheduler (потоки — единицы планирования внутри процесса)
  Fault isolation:  НЕТ — crash thread = потенциальный crash process
  Overhead:         ~1-2MB per thread (новый V8 isolate, shared heap possible)
  Scalability:      Offload CPU-bound tasks от event loop


═══════════════════════════════════════════════════════════════════════════
                           PORT MODEL
═══════════════════════════════════════════════════════════════════════════

OS Networking Stack:
  Port = 16-bit identifier (0-65535)
  Socket = (protocol, local_ip, local_port, remote_ip, remote_port)
  bind() = привязывает socket к порту
  Одн port ← один bind() (иначе EADDRINUSE)

CLUSTER — обход ограничения:
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Primary: socket_fd = socket() → bind(:3000) → listen()    │
│                          │                                  │
│           ┌──────────────┼──────────────┐                   │
│           ▼              ▼              ▼                   │
│     Process 1       Process 2       Process 3              │
│     accept(socket_fd)  accept(socket_fd)  accept(socket_fd)│
│                                                             │
│  Все вызывают accept() на ОДНОМ file descriptor             │
│  OS решает какой процесс получит следующее connection       │
│                                                             │
│  Результат: N процессов обрабатывают connections            │
│             через один TCP endpoint (:3000)                 │
└─────────────────────────────────────────────────────────────┘

WORKER THREADS — нет проблемы с портом:
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Main Thread: socket() → bind(:3000) → listen() → accept() │
│                    │                                        │
│                    │  "Пришёл запрос, нужно посчитать хеш"  │
│                    │                                        │
│                    ▼                                        │
│              worker.postMessage(data)                        │
│                    │                                        │
│                    ▼                                        │
│              Thread 1: compute(data) → postMessage(result)  │
│                                                             │
│  Threads НЕ вызывают bind/listen/accept                     │
│  Threads только выполняют computation                       │
│  Port принадлежит Main Thread                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘


═══════════════════════════════════════════════════════════════════════════
                         SUMMARY TABLE
═══════════════════════════════════════════════════════════════════════════

                        CLUSTER                 WORKER THREADS
─────────────────────────────────────────────────────────────────────────
OS primitive:           Process                 Thread
Address space:          Separate per worker     Shared (one process)
V8 instances:           N (one per process)     N (one per thread)
Event loops:            N (one per process)     N (one per thread)
Memory overhead:        ~50MB per worker        ~1-2MB per thread
Data sharing:           IPC (serialization)     SharedArrayBuffer (zero-copy)
Port handling:          Shared socket fd        Main Thread owns socket
Who handles HTTP:       All workers             Main Thread only
Fault isolation:        Full (process boundary) None (shared memory)
Use case:               Scale HTTP throughput   Offload CPU-bound work
Creation API:           cluster.fork()          new Worker(file)
Max practical count:    = CPU cores             Tens-hundreds
─────────────────────────────────────────────────────────────────────────
```

## Error

### Кто предоставляет объект Error

Три уровня происхождения

```
┌───────────────────────────���─────────────────────────────────────┐
│  Уровень 1: ECMA-262 (спецификация языка JavaScript)            │
│                                                                 │
│  Определяет: Error, TypeError, RangeError, ReferenceError,      │
│  SyntaxError, URIError, EvalError, AggregateError               │
│  Свойства: message, name, cause                                 │
│                                                                 │
│  Реализует: JavaScript ENGINE (V8, SpiderMonkey, JavaScriptCore)│
├─────────────────────────────────────────────────────────────────┤
│  Уровень 2: ПЛАТФОРМА (runtime)                                 │
│                                                                 │
│  Node.js добавляет:          Browser добавляет:                 │
│  - SystemError               - DOMException                     │
│  - error.code ('ENOENT')     - ErrorEvent                       │
│  - error.errno               - error.filename                   │
│  - error.syscall             - error.lineno                     │
│  - AbortError                - AbortError                       │
├─────────────────────────────────────────────────────────────────┤
│  Уровень 3: ПОЛЬЗОВАТЕЛЬСКИЙ КОД                               │
│                                                                 │
│  class MyError extends Error { ... }                            │
└─────────────────────────────────────────────────────────────────┘
```

Ключевой факт: и Chrome, и Node.js используют один и тот же V8 engine. Базовый Error — идентичен. Разница — в том, что платформа добавляет сверху.


#### Что определяет ECMAScript (одинаково ВЕЗДЕ)
```
// Конструкторы — из спецификации ECMA-262
new Error('something went wrong')
new TypeError('expected string, got number')
new RangeError('index out of bounds')
new ReferenceError('x is not defined')
new SyntaxError('Unexpected token')
new URIError('malformed URI')
new EvalError('eval error')             // почти не используется
new AggregateError([err1, err2], 'msg') // ES2021

// Стандартные свойства
const err = new Error('boom');
err.message    // 'boom'           — ES spec
err.name       // 'Error'          — ES spec
err.cause      // undefined        — ES2022: new Error('x', { cause: original })
err.stack      // '...'            — ⚠️ НЕ в спецификации, но реализован везде
```

🐦 `stack` реализован всеми движками, **но его формат не стандартизирован** — нет гарантии парсинга.

```
├── Error              ← message, name, cause

├── SyntaxError

Node.js добавляет поверх:
├── error.code         ← 'ENOENT', 'ERR_INVALID_ARG_TYPE'

├── DOMException       ← ошибки Web API
├── ErrorEvent         ← filename, lineno, colno
├── SecurityError      ← CORS, mixed content

```


### Зачем создавать объект Error

❗`Error` — это контейнер **диагностической информации**. 
Его главная ценность — `stack trace`: он фиксирует **точное место в коде, где произошла проблема**.

#### JavaScript позволяет `throw` любое значение:

```
throw 'something broke';          // строка
throw 404;                        // число
throw { status: 'fail' };         // объект
throw new Error('something broke'); // Error объект
```

#### при отладке:
```
// ❌ throw строку
throw 'something broke';

// В catch:
// err = 'something broke'
// err.stack = undefined     ← ГДЕ это произошло? НЕИЗВЕСТНО
// err.message = undefined
// typeof err = 'string'    ← нет методов, нет информации
```

#### при отладке с `Error`:
```
// ✅ throw Error
throw new Error('something broke');

// В catch:
// err.message = 'something broke'
// err.name = 'Error'
// err.stack = 
//   Error: something broke
//       at processPayment (/app/payments.js:47:11)    ← ТОЧНАЯ строка
//       at handleOrder (/app/orders.js:23:5)          ← кто вызвал
//       at Router.handle (/app/router.js:112:7)       ← откуда пришёл запрос
//       at Server.emit (node:events:513:28)           ← весь путь
```

#### Три свойства — три ответа на вопросы

| Свойство | Отвечает на вопрос | Значение |
| :-- | :-- | :-- |
| name | ЧТО за тип проблемы? | 'Error', 'TypeError', 'ValidationError' |
| message | КАКАЯ именно проблема? | 'User not found' |
| stack | ГДЕ это произошло? | Полный call stack с файлами и строками |


### How to Deliver Errors

#### Что значит «доставить» ошибку - у ошибки есть две стороны:
```
ПРОИЗВОДИТЕЛЬ ошибки              ПОТРЕБИТЕЛЬ ошибки
(код который обнаружил проблему)   (код который знает что с ней делать)
         │                                    ▲
         │    КАК ошибка попадает отсюда      │
         └────────────── СЮДА? ──────────────┘

```

#### `throw` — механика на уровне Call Stack

🐦 Выполнение с throw — **stack unwinding**

```
function third()  { throw new Error('boom'); }
function second() { return third(); }
function first()  { return second(); }
first();
```

```
Call Stack:                    throw → UNWINDING (размотка):

┌─────────────┐               
│   third()   │ ← throw!     third(): есть catch? НЕТ → убран, идём ниже
├─────────────┤               ┌─────────────┐
│  second()   │               │  second()   │ есть catch? НЕТ → убран
├─────────────┤               ├─────────────┤
│   first()   │               │   first()   │ есть catch? НЕТ → убран
├─────────────┤               ├─────────────┤
│   <global>  │               │   <global>  │ есть catch? НЕТ → 💀
└─────────────┘               └─────────────┘
                                             uncaughtException → process.exit(1)

```

#### Stack unwinding
— V8 последовательно снимает фреймы со стека, проверяя каждый: «есть ли здесь `try/catch`?». 
Если нет — фрейм уничтожается и V8 переходит к следующему ниже.


#### `try/catch` останавливает unwinding

```
function third()  { throw new Error('boom'); }
function second() { return third(); }
function first()  {
  try {
    return second();
  } catch (err) {
    console.log('Поймал:', err.message);
  }
}
first();
```

```
Call Stack:                    throw → UNWINDING:

┌─────────────┐               
│   third()   │ ← throw!     third(): есть catch? НЕТ → убран
├─────────────┤               ┌─────────────┐
│  second()   │               │  second()   │ есть catch? НЕТ → убран
├─────────────┤               ├─────────────┤
│   first()   │               │   first()   │ есть catch? ДА! ✅
├─────────────┤               ├─────────────┤       │
│   <global>  │               │   <global>  │       ▼
└─────────────┘               └─────────────┘  Выполняем блок catch
                                                err = Error('boom')
                                                console.log(...)
                                                
                                                Нормальный поток ВОССТАНОВЛЕН
                                                first() продолжает выполнение

```

#### Что конкретно происходит при unwinding

Когда фрейм снимается со стека, всё его состояние уничтожается:

```
function processOrder() {
  const connection = db.getConnection();     // ← ресурс захвачен
  const lock = mutex.acquire('orders');      // ← lock захвачен
  
  const user = getUser(userId);              // ← throw внутри!
  
  lock.release();                            // ← НЕ выполнится!
  connection.close();                        // ← НЕ выполнится!
  return result;                             // ← НЕ выполнится!
}
```

```
processOrder() снят со стека при unwinding:
  - connection — утечка (не закрыт)
  - lock — утечка (не отпущен)
  - Код после throw — НИКОГДА не выполнится
```

#### Поэтому используют `finally`:

```
function processOrder() {
  const connection = db.getConnection();
  try {
    const result = riskyOperation();
    return result;
  } catch (err) {
    // обработка ошибки
    throw err;  // можно перебросить дальше
  } finally {
    // ВСЕГДА выполнится — и при return, и при throw
    connection.close();  // ✅ ресурс освобождён в любом случае
  }
}
```


#### `throw` vs `return` — два способа выйти из функции

```
                    RETURN                         THROW
              ─────────────────              ─────────────────
Передаёт:     значение (результат)          Error (проблему)
Куда:          вызывающей функции            ближайшему catch (может быть далеко)
Поток:         нормальный                    аварийный (unwinding)
Промежуточные  выполняют код                 ПРОПУСКАЮТСЯ
функции:       после вызова                  (снимаются со стека)
```

```
// return — передача ВВЕРХ на один уровень
function getUser() {
  return { name: 'John' };  // → вызывающий получит значение
}

// throw — «прыжок» через ЛЮБОЕ количество уровней
function validateInput() {
  throw new Error('invalid');  // → может поймать catch в 5 уровнях выше
}
```

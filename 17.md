#### usage
```
95% of Node.js developers NEVER use these directly.

  http, https, Express, Fastify → use net underneath
  fetch, axios, got             → use dns underneath
  
  You USE them every day without knowing it.
  You rarely CALL them directly.

  But when you DO need them, nothing else will work.
```

#### never use for:
```
DON'T use net when:
  ✅ Building a REST API → use http/Express/Fastify
  ✅ Making HTTP requests → use fetch/axios/got
  ✅ WebSocket server → use ws package
  ✅ Connecting to Redis → use ioredis package
  ✅ Connecting to PostgreSQL → use pg package
  
  These all use net underneath. Let them handle it.

DON'T use dns when:
  ✅ Making HTTP requests → dns.lookup happens automatically
  ✅ Normal web server → DNS handled by OS and http module
  ✅ Connecting to databases → connection string handles resolution
```


### `node:net` — Raw TCP
```
net gives you raw TCP connections.
No HTTP. No headers. No status codes. No URLs.
Just raw bytes flowing between two machines.

  http module:
    "Send GET /api/users HTTP/1.1 with headers and get JSON back"
    
  net module:
    "Send these bytes. Receive some bytes back. That's it."

```

### Real project use cases

#### USE CASE 1: Custom protocol (non-HTTP)
```
USE CASE 1: Custom protocol (non-HTTP)
───────────────────────────────────────

  Not everything speaks HTTP.
  Databases, message queues, game servers use custom protocols.

  Redis protocol (RESP) is TCP, not HTTP:

    Client sends:  *3\r\n$3\r\nSET\r\n$4\r\nname\r\n$4\r\nAnna\r\n
    Server sends:  +OK\r\n

  This is NOT HTTP. It's raw bytes over TCP.
  The redis npm package uses net.Socket internally:
```

```
import net from 'net';

// This is (simplified) what the redis package does internally
const socket = net.createConnection({ host: '127.0.0.1', port: 6379 });

socket.on('connect', () => {
  // Send raw Redis protocol (RESP format)
  // *3 = array of 3 elements
  // $3 = string of length 3
  socket.write('*3\r\n$3\r\nSET\r\n$4\r\nname\r\n$4\r\nAnna\r\n');
});

socket.on('data', (buffer) => {
  console.log(buffer.toString()); // "+OK\r\n"
  // Redis responded with raw bytes, not HTTP, not JSON
});

// Same for MySQL, PostgreSQL, MongoDB, RabbitMQ, Memcached
// ALL database drivers use net.Socket under the hood
// because databases don't speak HTTP
```

```
  Packages that use net internally:
  
    ioredis / redis     → net.Socket to Redis (port 6379)
    mysql2 / pg         → net.Socket to database (3306 / 5432)
    mongodb             → net.Socket to MongoDB (27017)
    amqplib             → net.Socket to RabbitMQ (5672)
    
  You don't call net directly.
  But every database connection in your app goes through it.
```

#### USE CASE 2: Health check / port checker
```
USE CASE 2: Health check / port checker
────────────────────────────────────────

  "Is this service running? Can I connect to it?"
  
  Don't need HTTP. Just need to know if TCP port is open.
```

```
import net from 'net';

function isPortOpen(host, port, timeout = 3000) {
  return new Promise((resolve) => {
    const socket = new net.Socket();
    
    socket.setTimeout(timeout);
    
    socket.on('connect', () => {
      socket.destroy();
      resolve(true);     // port is open, service is running
    });
    
    socket.on('timeout', () => {
      socket.destroy();
      resolve(false);    // timed out, service might be down
    });
    
    socket.on('error', () => {
      resolve(false);    // connection refused, service is down
    });
    
    socket.connect(port, host);
  });
}

// Before starting your app, check dependencies:
async function checkDependencies() {
  const redis = await isPortOpen('redis.internal', 6379);
  const postgres = await isPortOpen('db.internal', 5432);
  const opensearch = await isPortOpen('search.internal', 9200);
  
  console.log(`Redis: ${redis ? '✅' : '❌'}`);
  console.log(`Postgres: ${postgres ? '✅' : '❌'}`);
  console.log(`OpenSearch: ${opensearch ? '✅' : '❌'}`);
  
  if (!redis || !postgres) {
    console.error('Critical dependencies unavailable. Exiting.');
    process.exit(1);
  }
}
```

#### USE CASE 3: TCP proxy / port forwarder
```
USE CASE 3: TCP proxy / port forwarder
───────────────────────────────────────

  Forward traffic from one port to another.
  Used in: development tunnels, service mesh sidecars, debugging.
```

```
import net from 'net';

// Forward all traffic from port 3000 to port 8000
// Useful for: local dev, debugging, simulating ALB

const proxy = net.createServer((clientSocket) => {
  // Someone connected to port 3000
  
  // Open connection to actual server on 8000
  const serverSocket = net.createConnection({ port: 8000 });
  
  // Pipe data both ways:
  // Client → Proxy → Server
  clientSocket.pipe(serverSocket);
  // Server → Proxy → Client  
  serverSocket.pipe(clientSocket);
  
  // That's it. Raw bytes flow through.
  // Works for HTTP, WebSocket, anything over TCP.
  
  clientSocket.on('error', () => serverSocket.destroy());
  serverSocket.on('error', () => clientSocket.destroy());
});

proxy.listen(3000, () => {
  console.log('Proxying port 3000 → 8000');
});
```

#### USE CASE 4: Custom TCP server (game server, IoT, chat)
```
USE CASE 4: Custom TCP server (game server, IoT, chat)
──────────────────────────────────────────────────────

  When HTTP is too heavy. You need your own lightweight protocol.
```

```
import net from 'net';

// Simple multiplayer game server
// Players send: "MOVE x y" or "SHOOT x y"
// Server broadcasts to all players

const clients = new Set();

const server = net.createServer((socket) => {
  clients.add(socket);
  console.log(`Player connected. Total: ${clients.size}`);
  
  socket.on('data', (buffer) => {
    const message = buffer.toString().trim();
    // message = "MOVE 10 20" or "SHOOT 5 8"
    
    // Broadcast to ALL other players
    for (const client of clients) {
      if (client !== socket && !client.destroyed) {
        client.write(message + '\n');
      }
    }
  });
  
  socket.on('close', () => {
    clients.delete(socket);
    console.log(`Player disconnected. Total: ${clients.size}`);
  });
  
  socket.on('error', (err) => {
    clients.delete(socket);
  });
});

server.listen(9000);

// Why not HTTP/WebSocket?
// - HTTP overhead: ~200 bytes of headers per message
// - TCP overhead: ~0 bytes extra (just your message)
// - For a game sending 60 messages/second, HTTP headers = wasted bandwidth
// - Custom binary protocol: 4 bytes (type + x + y) vs 200+ bytes HTTP
```

#### USE CASE 5: IPC (Inter-Process Communication)
```
USE CASE 5: IPC (Inter-Process Communication)
──────────────────────────────────────────────

  net supports Unix domain sockets — communication between
  processes on the SAME machine without network overhead.
```

```
import net from 'net';

// Worker process communicates with master process
// via Unix socket (no TCP overhead, no port needed)

// Master:
const server = net.createServer((socket) => {
  socket.on('data', (data) => {
    const task = JSON.parse(data.toString());
    const result = processTask(task);
    socket.write(JSON.stringify(result));
  });
});
server.listen('/tmp/myapp.sock');  // file path, not port number
//            ^^^^^^^^^^^^^^^^^^
//            Unix domain socket — lives on filesystem

// Worker:
const socket = net.createConnection('/tmp/myapp.sock');
socket.write(JSON.stringify({ type: 'search', query: '...' }));

// Why not HTTP?
//   Same machine communication.
//   Unix socket: ~2x faster than TCP localhost.
//   No port allocation. No TCP handshake. No network stack.
//   Used by: Docker, nginx, PM2, uWSGI internally.
```

### `node:dns` — DNS Lookups

```
dns resolves domain names to IP addresses.

  "api.example.com" → "93.184.216.34"

  Every HTTP request does this automatically.
  You call fetch("https://api.example.com/search"):
  
    1. Node.js calls dns.lookup("api.example.com") internally
    2. Gets IP: 93.184.216.34
    3. Opens TCP connection to 93.184.216.34:443
    4. Sends HTTP request
    
  You never see step 1-2. It happens inside http/https module.
```

#### USE CASE 1: Service discovery
```
USE CASE 1: Service discovery
─────────────────────────────

  In microservices, services find each other via DNS.
  But DNS can be STALE (cached for too long).
  Sometimes you need to manually resolve and control behavior.
```

```
import dns from 'dns/promises';

// Your ECS service registers with AWS Cloud Map (DNS-based discovery)
// search-service.internal → multiple container IPs

async function discoverService(serviceName) {
  try {
    // Resolve to ALL IP addresses (multiple containers)
    const addresses = await dns.resolve4(`${serviceName}.internal`);
    // addresses = ['10.0.1.50', '10.0.1.51', '10.0.1.52']
    //              container A    container B    container C
    
    console.log(`${serviceName} has ${addresses.length} instances`);
    return addresses;
    
  } catch (err) {
    if (err.code === 'ENOTFOUND') {
      console.error(`Service ${serviceName} not found in DNS`);
      // Service is down, not registered, or DNS misconfigured
    }
    throw err;
  }
}

// Pick a random instance (poor man's load balancing)
const instances = await discoverService('search-service');
const target = instances[Math.floor(Math.random() * instances.length)];
// Now connect directly to that container IP
```

#### USE CASE 2: DNS-based health monitoring
```
USE CASE 2: DNS-based health monitoring
────────────────────────────────────────

  "Is our DNS configured correctly? Are records propagated?"
```

```
import dns from 'dns/promises';

async function auditDNS(domain) {
  console.log(`\nAuditing DNS for: ${domain}\n`);
  
  // A records: domain → IPv4
  try {
    const ips = await dns.resolve4(domain);
    console.log(`  A records:     ${ips.join(', ')}`);
    // "93.184.216.34" → the server IP
  } catch { console.log('  A records:     NONE'); }
  
  // AAAA records: domain → IPv6
  try {
    const ips = await dns.resolve6(domain);
    console.log(`  AAAA records:  ${ips.join(', ')}`);
  } catch { console.log('  AAAA records:  NONE'); }
  
  // CNAME records: domain → another domain name
  try {
    const cnames = await dns.resolveCname(domain);
    console.log(`  CNAME records: ${cnames.join(', ')}`);
    // "d1234.cloudfront.net" → CDN distribution
  } catch { console.log('  CNAME records: NONE'); }
  
  // MX records: mail servers
  try {
    const mx = await dns.resolveMx(domain);
    mx.forEach(r => console.log(`  MX record:     ${r.exchange} (priority ${r.priority})`));
    // "mail.google.com (priority 10)" → Gmail handles email
  } catch { console.log('  MX records:    NONE'); }
  
  // TXT records: verification, SPF, DKIM
  try {
    const txt = await dns.resolveTxt(domain);
    txt.forEach(r => console.log(`  TXT record:    ${r.join('')}`));
    // "v=spf1 include:_spf.google.com ~all" → email auth
  } catch { console.log('  TXT records:   NONE'); }
  
  // NS records: nameservers
  try {
    const ns = await dns.resolveNs(domain);
    console.log(`  NS records:    ${ns.join(', ')}`);
    // "ns-123.awsdns-45.com" → Route 53 handles DNS
  } catch { console.log('  NS records:    NONE'); }
}

await auditDNS('astrazeneca.com');

// Output:
//   A records:     93.184.216.34, 93.184.216.35
//   CNAME records: NONE
//   MX records:    mail.astrazeneca.com (priority 10)
//   TXT records:   v=spf1 include:_spf.google.com ~all
//   NS records:    ns-123.awsdns-45.com, ns-456.awsdns-78.net
```

#### USE CASE 3: Deployment verification
```
USE CASE 3: Deployment verification
────────────────────────────────────

  After deploying, verify DNS points to the right place.
```

```
import dns from 'dns/promises';

async function verifyDeployment() {
  const domain = 'answer.astrazeneca.com';
  
  // Resolve and check it points to CloudFront
  const cnames = await dns.resolveCname(domain);
  const pointsToCloudFront = cnames.some(c => c.includes('cloudfront.net'));
  
  if (!pointsToCloudFront) {
    console.error(`❌ ${domain} does NOT point to CloudFront!`);
    console.error(`   Points to: ${cnames.join(', ')}`);
    process.exit(1);
  }
  
  console.log(`✅ ${domain} → ${cnames[0]} (CloudFront)`);
  
  // Reverse lookup: IP → hostname
  const ips = await dns.resolve4(cnames[0]);
  for (const ip of ips) {
    try {
      const hostnames = await dns.reverse(ip);
      console.log(`   ${ip} → ${hostnames.join(', ')}`);
    } catch {
      console.log(`   ${ip} → (no reverse DNS)`);
    }
  }
}
```

#### USE CASE 4: `dns.lookup` vs `dns.resolve` — the important difference
```
import dns from 'dns/promises';

// dns.lookup — uses OS resolver (reads /etc/hosts, OS cache)
const { address } = await dns.lookup('localhost');
// address = '127.0.0.1'
// This checks /etc/hosts FIRST, then DNS servers
// This is what http module uses internally
// Runs on libuv thread pool (can be bottleneck!)

// dns.resolve4 — queries DNS servers directly (bypasses OS)
const addresses = await dns.resolve4('api.example.com');
// addresses = ['93.184.216.34']
// Skips /etc/hosts, skips OS cache
// Queries DNS servers directly
// Does NOT use libuv thread pool (fully async)


// WHY THIS MATTERS:

// dns.lookup uses the libuv thread pool (default: 4 threads)
// Every HTTP request does a dns.lookup internally
// If you make 100 concurrent HTTP requests to different domains:
//   → 100 dns.lookup calls
//   → only 4 can run at a time (thread pool limit)
//   → 96 wait in queue
//   → EVERYTHING SLOWS DOWN

// Fix: increase thread pool
// Set BEFORE any require/import:
// process.env.UV_THREADPOOL_SIZE = 64;

// Or use dns.resolve (doesn't use thread pool):
// Fully async, no thread pool bottleneck
```

#### USE CASE 5: Custom DNS caching (performance)
```
USE CASE 5: Custom DNS caching (performance)
─────────────────────────────────────────────

  Node.js does NOT cache DNS lookups by default.
  Every HTTP request → new DNS lookup → 5-50ms overhead.
  For high-throughput APIs calling external services, this adds up.
```

```
import dns from 'dns/promises';

// Simple DNS cache
const dnsCache = new Map();
const TTL = 60_000; // 1 minute

async function cachedResolve(hostname) {
  const cached = dnsCache.get(hostname);
  
  if (cached && Date.now() - cached.timestamp < TTL) {
    return cached.address;  // cache hit, skip DNS query
  }
  
  const { address } = await dns.lookup(hostname);
  dnsCache.set(hostname, { address, timestamp: Date.now() });
  return address;
}

// In real projects, use packages like:
//   cacheable-lookup (used by got HTTP client)
//   dns-cache
// They hook into http.Agent to cache automatically
```

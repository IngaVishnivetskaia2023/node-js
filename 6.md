## Child process: запуск системных команд из Node.js

```
Node.js — это один процесс, выполняющий JavaScript.
Но иногда нужно:

- Выполнить shell-команду (ls, grep, git, ffmpeg, python)
- Запустить другую программу
- Использовать системные утилиты
- Параллельно выполнить тяжёлую задачу

child_process = создание НОВОГО процесса ОС из Node.js
```

```
┌─────────────────────────────────┐
│     Твой Node.js процесс        │
│     (parent / родитель)          │
│                                  │
│  const { exec } = require       │
│    ('child_process');            │
│                                  │
│  exec('ls -la')  ────────────────────→  ┌─────────────────────┐
│                                  │      │  Child Process       │
│                                  │      │  (дочерний процесс)  │
│                                  │      │                     │
│  получает stdout ←───────────────────── │  выполняет: ls -la  │
│                                  │      │  возвращает: stdout  │
│                                  │      └─────────────────────┘
└─────────────────────────────────┘

Это ДВА процесса ОС — отдельная память, отдельный PID.
```

## 1. exec() — выполнить команду в shell
#### Что делает:
Запускает shell (bash/cmd/powershell), передаёт туда команду как строку, собирает весь вывод в буфер, возвращает целиком.

```
import { exec } from 'node:child_process';

exec('ls -la /home/user', (err, stdout, stderr) => {
  if (err) {
    console.error('Ошибка:', err.message);
    return;
  }
  if (stderr) {
    console.error('Stderr:', stderr);
    return;
  }
  console.log('Результат:', stdout);
});
```

#### Promise-версия
```
import { exec } from 'node:child_process';
import { promisify } from 'node:util';

const execAsync = promisify(exec);

const { stdout, stderr } = await execAsync('git log --oneline -5');
console.log(stdout);
```

#### Что происходит внутри

```
exec('ls -la | grep .js')

Node.js:
  1. Запускает /bin/bash (или cmd.exe на Windows)
  2. Передаёт строку "ls -la | grep .js" в shell
  3. Shell парсит команду (включая pipes |, &&, >, *)
  4. Shell выполняет
  5. Весь stdout копится в БУФЕР (в памяти)
  6. Когда процесс завершился → callback(err, stdout, stderr)
```

#### Особенности

```
// ✅ Поддерживает shell-фичи (pipes, redirect, glob):
exec('cat file.txt | grep error > errors.log');
exec('ls *.js');
exec('echo $HOME');
exec('command1 && command2');

// ⚠️ БУФЕРИЗУЕТ весь вывод (по умолчанию лимит 1MB):
exec('find / -name "*.log"', { maxBuffer: 1024 * 1024 * 10 }, callback);
// Если вывод > maxBuffer → ошибка

// ❌ ОПАСНО — shell injection:
const userInput = '; rm -rf /';
exec(`ls ${userInput}`);  // 💀 выполнит: ls ; rm -rf /
```

### 2. execFile() — запуск конкретного файла (без shell)

#### Что делает
Запускает **исполняемый файл напрямую** — без shell. Аргументы передаются массивом, а не строкой.we

```
import { execFile } from 'node:child_process';

execFile('git', ['log', '--oneline', '-5'], (err, stdout, stderr) => {
  if (err) {
    console.error('Ошибка:', err.message);
    return;
  }
  console.log(stdout);
});
```

#### Преимущества

```
// ✅ Безопаснее — нет shell injection:
const userInput = '; rm -rf /';
execFile('ls', [userInput]);
// Ищет файл с БУКВАЛЬНЫМ именем "; rm -rf /" — не выполняет как команду

// ✅ Быстрее — нет оверхеда запуска shell

// ❌ Нет shell-фич (pipes, glob, redirect):
execFile('ls', ['*.js']);       // ❌ Ищет файл буквально "*.js"
execFile('cat', ['|', 'grep']); // ❌ | не обработается
```

### 3. spawn() — потоковый запуск (для больших данных)
#### Что делает
Запускает процесс и даёт доступ к его `stdout`/`stderr` как `stream` (поток данных) — не буферизует всё в памяти.

```
import { spawn } from 'node:child_process';

const child = spawn('find', ['/', '-name', '*.log']);

// stdout — это readable stream (данные ТЕКУТ порциями):
child.stdout.on('data', (chunk) => {
  console.log('Порция данных:', chunk.toString());
});

child.stderr.on('data', (chunk) => {
  console.error('Ошибка:', chunk.toString());
});

child.on('close', (code) => {
  console.log(`Процесс завершён с кодом: ${code}`);
});
```

```
exec():                               spawn():
──────                                ───────
Буферизует ВЕСЬ вывод                  Отдаёт порциями (stream)
Callback после ЗАВЕРШЕНИЯ              Events по мере выполнения
Лимит ~1MB по умолчанию               Нет лимита
Для: маленький вывод                   Для: большой / бесконечный вывод

exec('find /'):                        spawn('find', ['/']):
  Ждёт пока find закончит               Получает результаты СРАЗУ
  Копит ВСЁ в RAM                        По 64KB за раз
  Может кончиться память                  Память стабильная
  Callback с полным результатом          Events: data, data, data... close
```

```
exec:
  [════════════════════════════] → callback(stdout)  // всё сразу в конце
  
spawn:
  [══] → data  [══] → data  [══] → data  [══] → close  // по частям
```


### 4. fork() — запуск другого Node.js скрипта

#### Что делает
Специальный вариант `spawn()` **для запуска другого Node.js файла с встроенным каналом связи** (IPC — Inter-Process Communication).

```
// parent.js
import { fork } from 'node:child_process';

const child = fork('./heavy-task.js');

// Отправить данные дочернему процессу:
child.send({ task: 'compute', data: [1, 2, 3, 4, 5] });

// Получить результат:
child.on('message', (result) => {
  console.log('Результат:', result);  // { sum: 15 }
});
```

#### Зачем fork если есть spawn

```
spawn('node', ['script.js']):
  - Запускает Node.js
  - Общение через stdin/stdout (текст)
  - Нужно сериализовать/парсить вручную

fork('./script.js'):
  - Запускает Node.js (автоматически)
  - Встроенный IPC канал
  - .send(object) / .on('message') — JSON автоматически
  - Удобнее для Node.js ↔ Node.js коммуникации
```

#### Зачем нужен отдельный процесс для Node.js кода

```
Проблема: Node.js — однопоточный (один event loop)

Тяжёлая вычислительная задача БЛОКИРУЕТ сервер:

// ❌ Блокирует event loop — все клиенты ждут:
app.get('/report', (req, res) => {
  const result = heavyComputation(data);  // 10 секунд CPU
  res.json(result);
  // Все остальные запросы СТОЯТ 10 секунд!
});

// ✅ Выносим в отдельный процесс:
app.get('/report', (req, res) => {
  const child = fork('./compute-report.js');
  child.send({ data });
  child.on('message', (result) => {
    res.json(result);
  });
  // Event loop СВОБОДЕН — другие запросы обрабатываются!
});
```

|  | exec | execFile | spawn | fork |
| :-- | :-- | :-- | :-- | :-- |
| Shell | ✅ Да | ❌ Нет | ⚠️ Опционально | ❌ Нет |
| Вывод | Буфер (целиком) | Буфер (целиком) | Stream (порциями) | IPC (messages) |
| Pipes/Glob | ✅ | ❌ | С shell: true | ❌ |
| Безопасность | ❌ Injection | ✅ Безопасно | ✅ Безопасно | ✅ Безопасно |
| Большой вывод | ❌ maxBuffer | ❌ maxBuffer | ✅ Нет лимита | — |
| Для чего | Быстрые shell-команды | Конкретная программа | Длительные процессы | Node.js параллельность |
| Когда | git status, whoami | git, ffmpeg | find /, live logs | CPU-тяжёлые задачи |


```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   Нужна shell-команда (pipes, &&, >, *)?                       │
│       → exec()                                                  │
│       "ls -la | grep .js | wc -l"                              │
│                                                                 │
│   Запуск конкретной программы, вывод небольшой?                 │
│       → execFile()                                              │
│       execFile('git', ['status'])                               │
│                                                                 │
│   Вывод большой / нужен по мере генерации?                     │
│       → spawn()                                                 │
│       spawn('ffmpeg', [...]) — стримим прогресс                │
│       spawn('tail', ['-f', '/var/log/app.log']) — бесконечный  │
│                                                                 │
│   Тяжёлые вычисления в Node.js / параллельность?               │
│       → fork()                                                  │
│       fork('./worker.js') — не блокирует event loop            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```


```
В Node.js есть ТРИ способа параллелизма:

fork()            — отдельный ПРОЦЕСС (тяжёлый)
Worker Threads    — отдельный ПОТОК (как Web Worker!) 
cluster           — несколько процессов слушают один порт
```


## Процесс vs Поток (Process vs Thread)

### На уровне ОС

```
┌─────────────────────────────────────────────────────────────────────┐
│                          ОПЕРАЦИОННАЯ СИСТЕМА                        │
│                                                                     │
│  Процесс A (PID: 1001)        Процесс B (PID: 1002)               │
│  ┌───────────────────────┐    ┌───────────────────────┐            │
│  │  RAM: 0x0000-0xFFFF   │    │  RAM: 0x0000-0xFFFF   │            │
│  │  (СВОЁ адресное       │    │  (СВОЁ адресное       │            │
│  │   пространство)       │    │   пространство)       │            │
│  │                       │    │                       │            │
│  │  ┌─────┐ ┌─────┐     │    │  ┌─────┐ ┌─────┐     │            │
│  │  │ T1  │ │ T2  │     │    │  │ T1  │ │ T2  │     │            │
│  │  │     │ │     │     │    │  │     │ │     │     │            │
│  │  └──┬──┘ └──┬──┘     │    │  └─────┘ └─────┘     │            │
│  │     │       │         │    │                       │            │
│  │     └───┬───┘         │    │                       │            │
│  │         ▼             │    │                       │            │
│  │   Общая RAM процесса  │    │   Общая RAM процесса  │            │
│  └───────────────────────┘    └───────────────────────┘            │
│         │                              │                            │
│         └──── НЕ ВИДЯТ друг друга ─────┘                           │
│               (изолированы ОС)                                     │
└─────────────────────────────────────────────────────────────────────┘
```

#### Ключевые отличия

|  | Процесс (Process) | Поток (Thread) |
| :-- | :-- | :-- |
| Память | СВОЯ (изолированная) | ОБЩАЯ (с другими потоками процесса) |
| Создание | Тяжёлое (~30-50MB, ~100ms) | Лёгкое (~1-2MB, ~1ms) |
| Crash | Умирает ОДИН, остальные живы | Умирает ВЕСЬ процесс |
| Общение | IPC — медленно (через ОС) | Shared memory — мгновенно |
| Изоляция | Полная (ОС гарантирует) | Нет (баг в одном потоке = crash всех) |
| Количество | Десятки-сотни | Тысячи |


### Как это работает в БРАУЗЕРЕ
```
Chrome при открытии трёх табов:

┌──── Процесс: Chrome Main (PID: 1001) ──────────────────┐
│  UI браузера, адресная строка, закладки                  │
└─────────────────────────────────────────────────────────┘

┌──── Процесс: Tab 1 — google.com (PID: 1002) ──────────┐
│                                                         │
│  ┌─────────────────┐  ┌──────────────┐                 │
│  │  Main Thread    │  │ Web Worker   │                  │
│  │  (JS + DOM +    │  │ (JS only,    │                  │
│  │   layout +      │  │  no DOM)     │                  │
│  │   paint)        │  │              │                  │
│  └─────────────────┘  └──────────────┘                  │
│                                                         │
│  Общая RAM этого процесса                               │
└─────────────────────────────────────────────────────────┘

┌──── Процесс: Tab 2 — youtube.com (PID: 1003) ─────────┐
│                                                         │
│  ┌─────────────────┐  ┌──────────────┐                 │
│  │  Main Thread    │  │ Web Worker   │                  │
│  └─────────────────┘  └──────────────┘                  │
│                                                         │
└─────────────────────────────────────────────────────────┘

┌──── Процесс: Tab 3 — evil-site.com (PID: 1004) ───────┐
│                                                         │
│  ┌─────────────────┐                                    │
│  │  Main Thread    │                                    │
│  └─────────────────┘                                    │
│                                                         │
│  НЕ МОЖЕТ достучаться до RAM процесса Tab 1            │
│  НЕ МОЖЕТ прочитать данные google.com                   │
│  Crash здесь → только эта вкладка падает                │
└─────────────────────────────────────────────────────────┘
```

#### Почему Chrome использует процессы для табов
```
Если бы все табы = потоки одного процесса:
  ❌ evil-site.com мог бы читать RAM google.com (общая память!)
  ❌ Crash в одном табе убил бы ВСЕ табы
  ❌ Зависший таб заморозил бы весь браузер

Каждый таб = отдельный процесс:
  ✅ evil-site.com изолирован (своя RAM, невидима другим)
  ✅ Crash одного таба → "Aw, Snap!" только в нём
  ✅ Зависший таб не влияет на остальные
  ⚠️ Цена: больше RAM (каждый процесс ~50-100MB)
     (поэтому Chrome "жрёт" оперативку)
```

```

                        ПРОЦЕСС
                     (тяжёлый, изолированный)
                    ┌─────────────────────┐
                    │                     │

  Поток = Worker Thread (внутри того же node)
```

## Что использовать

```
НУЖНА ИЗОЛЯЦИЯ (crash safety, security):
  → Процесс
  Примеры:
    - Chrome: каждый таб (вредоносный сайт не достанет другие)
    - Node.js fork(): плагин может крашнуться — основной сервер выжи��ет
    - Microservices: сервисы в разных процессах/контейнерах

НУЖНА СКОРОСТЬ + SHARED DATA:
  → Поток
  Примеры:
    - Web Worker: тяжёлые вычисления (парсинг, crypto) без тормоза UI
    - Worker Thread: CPU-интенсивная задача, можно шарить ArrayBuffer
    - libuv thread pool: параллельные fs/dns операции

КРИТЕРИЙ ВЫБОРА:
  Процесс: "Если оно сломается — остальное должно работать"
  Поток: "Мне нужна скорость и общие данные, crash маловероятен"
```

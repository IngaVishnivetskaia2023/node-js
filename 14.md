## Node.js `http` Module 

#### What `http.createServer()` actually does

```
import http from 'http';

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain' });
  res.end('Hello World');
});

server.listen(3000);
```


```
What happens when you call createServer():

  1. Creates a net.Server (TCP server) underneath
  2. Wraps it with HTTP parsing logic
  3. Returns an http.Server instance (which IS an EventEmitter)
  4. Does NOT start listening yet (lazy — waits for .listen())


  http.Server
    └── extends net.Server
          └── extends EventEmitter

  When you call server.listen(3000):
    1. Binds to port 3000 on all interfaces (0.0.0.0)
    2. OS kernel starts accepting TCP connections on that port
    3. Node.js event loop polls for incoming connections
    4. For each connection, HTTP parser processes raw bytes into req/res


  The callback you pass to createServer:
    (req, res) => { ... }
    
  This is just shorthand for:
    server.on('request', (req, res) => { ... })
    
  Both are equivalent. The 'request' event fires for each HTTP request.
```

#### The full lifecycle of an HTTP request

```
Client sends: POST /api/users HTTP/1.1

  Step 1: TCP CONNECTION
  ──────────────────────

  OS kernel: "Incoming TCP connection on port 3000"
  Node.js event loop: polls and detects new connection
  net.Server: emits 'connection' event with raw TCP socket
  http.Server: wraps socket with HTTP parser

  server.on('connection', (socket) => {
    // raw TCP socket — you rarely need this
    // socket is a net.Socket (Duplex stream, EventEmitter)
  });


  Step 2: HTTP PARSING
  ────────────────────

  Raw bytes arrive on the TCP socket:
  
  "POST /api/users HTTP/1.1\r\n
   Host: localhost:3000\r\n
   Content-Type: application/json\r\n
   Content-Length: 27\r\n
   \r\n
   {"name":"Anna","age":30}"

  Node.js uses llhttp (C parser) to parse these bytes.
  llhttp is extremely fast — written in C, compiled to native code.
  
  Parser extracts:
    method:  "POST"
    url:     "/api/users"
    headers: { host: "localhost:3000", "content-type": "application/json", ... }
    
  Parser creates:
    req = new http.IncomingMessage(socket)   ← Readable Stream
    res = new http.ServerResponse(req)       ← Writable Stream


  Step 3: 'request' EVENT
  ───────────────────────

  http.Server emits 'request' event with (req, res).
  Your callback fires:

  (req, res) => {
    // req.method  = "POST"
    // req.url     = "/api/users"
    // req.headers = { host: "localhost:3000", ... }
    // req body?   NOT here yet. Must read from stream.
  }


  Step 4: BODY ARRIVES (streamed)
  ───────────────────────────────

  The body is NOT parsed automatically.
  It streams in as chunks via the Readable stream (req):

  req.on('data', (chunk) => {
    // chunk = Buffer containing part of the body
    // for small bodies: one chunk with entire body
    // for large bodies: many chunks
  });

  req.on('end', () => {
    // all chunks received, body is complete
  });


  Step 5: YOU SEND RESPONSE
  ─────────────────────────

  res.writeHead(201, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify({ id: 1, name: 'Anna' }));

  This writes to the Writable stream (res):
    → res serializes to HTTP response text
    → writes to underlying TCP socket
    → bytes travel over network to client


  Step 6: CONNECTION HANDLING
  ──────────────────────────

  HTTP/1.1 keep-alive (default):
    TCP connection stays open for more requests.
    Next request on same connection → repeat from Step 2.
    
  Connection: close:
    TCP connection closed after response.
    Socket destroyed, file descriptor freed.
```

```
VISUAL TIMELINE:

  TCP socket          llhttp parser         Your callback
     │                     │                      │
     │── raw bytes  ──────→│                      │
     │  "POST /api..."     │── req, res ─────────→│
     │                     │                      │
     │── body bytes  ─────→│── 'data' event ─────→│  chunk 1
     │── body bytes  ─────→│── 'data' event ─────→│  chunk 2
     │── (end of body)  ──→│── 'end' event ──────→│  body complete
     │                     │                      │
     │                     │        res.writeHead + res.end
     │                     │                      │
     │←── response bytes ──│←─── response ────────│
     │                     │                      │
     │  (connection stays open for next request)  │
```

#### `req` — IncomingMessage (Readable Stream)

```
req is http.IncomingMessage

  Inheritance chain:
    http.IncomingMessage
      └── extends stream.Readable
            └── extends EventEmitter


  IMMEDIATE properties (available when callback fires):
  ─────────────────────────────────────────────────────

    req.method        "POST"
    req.url           "/api/users?role=admin"
    req.headers       { 'content-type': 'application/json', ... }
    req.httpVersion   "1.1"
    req.socket        the underlying TCP socket

    ⚠️ req.url is RAW — not parsed.
    "/api/users?role=admin" is a string, not an object.
    
    To parse it:
      const url = new URL(req.url, `http://${req.headers.host}`);
      url.pathname   // "/api/users"
      url.searchParams.get('role')  // "admin"

    ⚠️ req.headers keys are ALWAYS lowercase in Node.js.
    Client sends "Content-Type" → you read req.headers['content-type']


  BODY (must read from stream):
  ─────────────────────────────

    The body is NOT a property. It's a stream of bytes.
    You must collect it yourself:

    const chunks = [];
    
    req.on('data', (chunk) => {
      // chunk is a Buffer (raw bytes)
      // small body: 1 chunk with everything
      // large body (file upload): many chunks (16KB-64KB each)
      chunks.push(chunk);
    });

    req.on('end', () => {
      const body = Buffer.concat(chunks).toString();
      // body = '{"name":"Anna","age":30}'
      const parsed = JSON.parse(body);
      // parsed = { name: "Anna", age: 30 }
    });

    req.on('error', (err) => {
      // connection dropped, client disconnected, etc.
    });
```


#### Why isn't the `body` just a property?

```
Express gives you req.body. Why doesn't Node.js?

  BECAUSE THE BODY MIGHT BE HUGE:

  Scenario 1: JSON (small)
    Body: {"name":"Anna"}
    Size: 17 bytes
    One chunk. Fits in memory. Easy.

  Scenario 2: File upload (large)  
    Body: 2GB video file
    Size: 2,147,483,648 bytes
    Can't load into memory. Must process chunk by chunk.

  Scenario 3: Streaming (continuous)
    Body: live audio stream
    Size: infinite (keeps coming)
    NEVER fully arrives. Must process in real-time.


  Node.js gives you the RAW STREAM because:
    - It works for ALL sizes (17 bytes or 2GB)
    - It never buffers more than one chunk in memory
    - You decide how to handle it (buffer, stream, pipe to file)
    
  Express's req.body = middleware that collects chunks for you:
    app.use(express.json())  ← reads all chunks, JSON.parses, puts on req.body
    Only works for small bodies. Would crash on 2GB upload.


  ┌────────────────────────────────────────────────────────────┐
  │                                                            │
  │  Node.js http: "Here are bytes as they arrive. You deal."  │
  │  Express:      "I'll collect them for you (if they're      │
  │                 small enough)."                            │
  │  FastAPI:      Same concept — Body(...) reads the stream   │
  │                                                            │
  └────────────────────────────────────────────────────────────┘
```



#### `res` — ServerResponse (Writable Stream)

```
res is http.ServerResponse

  Inheritance chain:
    http.ServerResponse
      └── extends http.OutgoingMessage
            └── extends stream.Writable
                  └── extends EventEmitter


  THE THREE PHASES OF A RESPONSE:
  ───────────────────────────────

  Phase 1: Set status + headers (before any body is sent)
  
    res.statusCode = 201;
    res.setHeader('Content-Type', 'application/json');
    res.setHeader('X-Request-Id', 'abc-123');
    
    // Or all at once:
    res.writeHead(201, {
      'Content-Type': 'application/json',
      'X-Request-Id': 'abc-123'
    });
    
    ⚠️ Headers must be set BEFORE writing body.
    Once you call res.write() or res.end(), headers are sent.
    Calling res.setHeader() after that → throws Error.


  Phase 2: Write body (can be called multiple times)
  
    res.write('{"results":');       // sends first chunk
    res.write('[1,2,3,4,5]');       // sends second chunk
    res.write('}');                  // sends third chunk
    
    Each write() sends data to the client immediately.
    Client receives chunks as they're sent.
    This is HOW SSE works — write() called repeatedly.


  Phase 3: End response (must call exactly once)
  
    res.end();                      // no more data, finish response
    // or
    res.end('{"status":"ok"}');     // send final chunk + finish
    
    After end():
      - Response is complete
      - Client receives all data
      - No more writes allowed
      - 'finish' event emits on res
      - TCP connection returned to pool (keep-alive) or closed
```

```
COMMON MISTAKE — why responses hang:

  // ❌ BROKEN: response never ends
  const server = http.createServer((req, res) => {
    res.writeHead(200);
    res.write('Hello');
    // forgot res.end() → client waits forever
    // browser spinner keeps spinning
    // connection stays open until timeout
  });

  // ✅ CORRECT: always end the response
  const server = http.createServer((req, res) => {
    res.writeHead(200);
    res.end('Hello');    // write + end in one call
  });
```

#### Everything is `EventEmitter` — the complete picture

```
  http.Server (extends EventEmitter):
  ────────────────────────────────────
  
    server.on('request', (req, res) => {})     most important — HTTP request arrived
    server.on('connection', (socket) => {})    raw TCP connection established
    server.on('close', () => {})               server stopped
    server.on('error', (err) => {})            server error (port in use, etc.)
    server.on('listening', () => {})           server started
    server.on('upgrade', (req, socket) => {})  WebSocket upgrade request!

  
  req — IncomingMessage (extends Readable → EventEmitter):
  ─────────────────────────────────────────────────────────
  
    req.on('data', (chunk) => {})     body chunk arrived
    req.on('end', () => {})           body complete
    req.on('error', (err) => {})      read error
    req.on('close', () => {})         connection closed (client disconnected)
    req.on('aborted', () => {})       request aborted by client (deprecated)
    

  res — ServerResponse (extends Writable → EventEmitter):
  ────────────────────────────────────────────────────────
  
    res.on('finish', () => {})        response fully sent
    res.on('close', () => {})         connection closed before finish
    res.on('error', (err) => {})      write error
    res.on('drain', () => {})         safe to write more (backpressure relief)
    res.on('pipe', (src) => {})       something piped to this stream


  socket — net.Socket (extends Duplex → EventEmitter):
  ────────────────────────────────────────────────────
  
    socket.on('data', (chunk) => {})     raw TCP data
    socket.on('end', () => {})           other side finished sending
    socket.on('close', () => {})         connection fully closed
    socket.on('error', (err) => {})      TCP error
    socket.on('timeout', () => {})       idle too long
```

```
HOW THEY CONNECT:

  ┌─────────────────────────────────────────────────────────────┐
  │                                                             │
  │  TCP Socket (raw bytes in both directions)                  │
  │  ┌───────────────────────────────────────────────────────┐  │
  │  │                                                       │  │
  │  │  req (Readable) ← reads FROM socket                   │  │
  │  │    Incoming bytes → llhttp parser → data events       │  │
  │  │                                                       │  │
  │  │  res (Writable) → writes TO socket                    │  │
  │  │    Your writes → HTTP serializer → outgoing bytes     │  │
  │  │                                                       │  │
  │  └────────────────────���─────────────────────────────┘  │
  │                                                             │
  │  Both req and res wrap the SAME underlying TCP socket.      │
  │  req.socket === res.socket  // true                         │
  │                                                             │
  └─────────────────────────────────────────────────────────────┘
```


#### Complete POST handler — annotated

```
import http from 'http';

const server = http.createServer((req, res) => {
  
  // ─── ROUTING ──────────────────────────────────────────────
  // Node.js http has NO router. You check method + url manually.
  
  if (req.method === 'POST' && req.url === '/api/users') {
    
    // ─── COLLECT BODY CHUNKS ──────────────────────────────────
    // req is a Readable stream. Body arrives in chunks.
    
    const chunks = [];
    
    req.on('data', (chunk) => {
      // chunk: Buffer (raw bytes)
      // 
      // Why Buffer, not string?
      //   HTTP body can be ANYTHING: JSON, image, video, binary
      //   Buffer handles all of these. Strings can't hold binary.
      //
      // For small bodies (< 64KB): usually ONE chunk
      // For large bodies: many chunks (~16KB each)
      //
      // Memory: only current chunk is in memory
      //         previous chunks in the array wait for concat
      
      chunks.push(chunk);
    });
    
    
    req.on('end', () => {
      // All chunks received. Body is complete.
      
      // Buffer.concat: merges all chunks into one Buffer
      // .toString(): converts Buffer to UTF-8 string
      const rawBody = Buffer.concat(chunks).toString();
      // rawBody = '{"name":"Anna","age":30}'
      
      // JSON.parse: string → JavaScript object
      try {
        const body = JSON.parse(rawBody);
        // body = { name: "Anna", age: 30 }
        
        // ─── SEND RESPONSE ─────────────────────────────────────
        // Phase 1: status + headers
        res.writeHead(201, { 'Content-Type': 'application/json' });
        
        // Phase 2 + 3: body + end (combined)
        res.end(JSON.stringify({ id: 1, ...body }));
        // Sends: HTTP/1.1 201 Created
        //        Content-Type: application/json
        //        {"id":1,"name":"Anna","age":30}
        
      } catch (err) {
        // JSON.parse failed — client sent invalid JSON
        res.writeHead(400, { 'Content-Type': 'application/json' });
        res.end(JSON.stringify({ error: 'Invalid JSON' }));
      }
    });
    
    
    req.on('error', (err) => {
      // Client disconnected, network error, etc.
      // Connection is dead — can't send response
      console.error('Request error:', err);
    });
    
    
  } else {
    // ─── ANY OTHER ROUTE ──────────────────────────────────────
    // No routing framework = manual 404 for everything else
    
    res.writeHead(404, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ error: 'Not Found' }));
  }
});


// ─── ERROR HANDLING ───────────────────────────────────────────
// Server-level errors (not request-level)

server.on('error', (err) => {
  if (err.code === 'EADDRINUSE') {
    console.error('Port 3000 already in use!');
    // Another process (maybe previous run) is using this port
  } else {
    console.error('Server error:', err);
  }
});


// ─── START LISTENING ──────────────────────────────────────────

server.listen(3000, () => {
  // 'listening' event fires when server is ready
  console.log('Server running on port 3000');
});
```


#### Streams + piping — the power of raw http

```
// Pipe a file directly to response WITHOUT loading into memory:

import http from 'http';
import fs from 'fs';

const server = http.createServer((req, res) => {
  
  if (req.method === 'GET' && req.url === '/video') {
    
    // ❌ BAD: loads entire 2GB file into memory
    // const data = fs.readFileSync('movie.mp4');
    // res.end(data);  // 2GB in RAM!
    
    // ✅ GOOD: streams file chunk by chunk
    res.writeHead(200, { 'Content-Type': 'video/mp4' });
    const fileStream = fs.createReadStream('movie.mp4');
    fileStream.pipe(res);
    // 
    // What pipe() does internally:
    //   fileStream.on('data', (chunk) => res.write(chunk));
    //   fileStream.on('end', () => res.end());
    //   fileStream.on('error', (err) => res.destroy(err));
    //   
    // Plus backpressure handling:
    //   if res.write() returns false (buffer full):
    //     fileStream.pause()  ← stop reading from disk
    //   when res emits 'drain' (buffer cleared):
    //     fileStream.resume() ← continue reading
    //
    // Memory usage: ~64KB at any time (one chunk)
    // NOT 2GB. Regardless of file size.
  }
  
  
  if (req.method === 'POST' && req.url === '/upload') {
    
    // Pipe request body directly to file
    const writeStream = fs.createWriteStream('uploaded-file.bin');
    req.pipe(writeStream);
    //
    // req (Readable) → pipe → writeStream (Writable)
    // Each chunk from client → written to disk immediately
    // 2GB upload? Still only ~64KB in memory.
    
    writeStream.on('finish', () => {
      res.writeHead(200);
      res.end('Upload complete');
    });
    
    writeStream.on('error', (err) => {
      res.writeHead(500);
      res.end('Upload failed');
    });
  }
});
```

```
THE PIPE MENTAL MODEL:

  Source (Readable)  →→→  Destination (Writable)
  
  req (client body)  →→→  fs.WriteStream (save to disk)
  fs.ReadStream      →→→  res (send to client)
  req (proxy)        →→→  outgoing request to another server

  Data flows through like water in a pipe.
  Only one "bucket" (chunk) is in transit at a time.
  
  
  BACKPRESSURE:
  
  What if destination is slower than source?
  (e.g., client uploads faster than disk can write)
  
  ┌──────────┐      ┌──────────┐     ┌──────────┐
  │  Source   │────→│  Buffer  │────→│   Dest   │
  │  (fast)  │      │  filling │     │  (slow)  │
  └──────────┘      │  up! ⚠️  │     └──────────┘
                    └──────────┘
  
  pipe() handles this automatically:
  
  1. res.write(chunk) returns false     "buffer is full!"
  2. pipe pauses the source             "stop reading"
  3. res emits 'drain'                  "buffer cleared, ready"
  4. pipe resumes the source            "continue reading"
  
  Without backpressure handling → memory fills up → crash.
  pipe() prevents this. Always use pipe() or pipeline().
```


#### How this maps to Express/Fastify

```
Express wraps the raw http module:

  Raw http:                          Express:
  ─────────                          ────────
  
  req.method === 'POST'              app.post('/api/users', ...)
  req.url === '/api/users'           ← routing handled for you
  
  chunks + end event                 req.body (middleware did this)
  JSON.parse(body)                   ← express.json() did this
  
  res.writeHead(200, headers)        res.status(200).json(data)
  res.end(JSON.stringify(data))      ← json() does both
  
  manual 404 for all routes          404 handler middleware
  
  req.headers['content-type']        req.headers['content-type']
                                     (same — Express doesn't change this)
  
  req.on('data'), req.on('end')      still available!
                                     Express adds helpers but doesn't
                                     remove raw stream access.


  Everything Express/Fastify/Koa does is built ON TOP of
  the raw http module. They add:
    - Routing
    - Body parsing (collecting chunks for you)
    - Middleware chain
    - Helper methods (res.json, res.redirect)
    - Error handling
    
  But underneath, it's always:
    http.createServer((req, res) => { ... })
    
  Understanding the raw module means you understand
  what every framework is doing for you.
```

#### Connection keep-alive — what actually happens

```
HTTP/1.1 DEFAULT: keep-alive

  Without keep-alive (HTTP/1.0):
  ──────────────────────────────
  
  TCP connect → Request 1 → Response 1 → TCP close
  TCP connect → Request 2 → Response 2 → TCP close
  TCP connect → Request 3 → Response 3 → TCP close
  
  3 TCP handshakes. 3 TLS handshakes. Expensive.


  With keep-alive (HTTP/1.1):
  ───────────────────────────
  
  TCP connect → Request 1 → Response 1
              → Request 2 → Response 2
              → Request 3 → Response 3
              → ... (reuse same connection)
              → timeout or Connection: close → TCP close
  
  1 TCP handshake. 1 TLS handshake. Fast.


  In Node.js:

  server.keepAliveTimeout = 5000;   // close after 5s idle (default)
  server.headersTimeout = 60000;    // max time to receive headers
  server.requestTimeout = 300000;   // max time for entire request
  server.maxRequestsPerSocket = 0;  // unlimited requests per connection
  
  
  THE 'connection' vs 'request' EVENTS:
  
  1 TCP connection can serve MANY HTTP requests.
  
  server.on('connection', (socket) => {
    // fires ONCE per TCP connection
    connectionCount++;  // e.g., 50 connections from 50 clients
  });
  
  server.on('request', (req, res) => {
    // fires for EACH HTTP request
    requestCount++;  // e.g., 5000 requests over those 50 connections
  });
  
  50 connections × 100 requests each = 5000 request events
                                       but only 50 connection events
```

## EventEmitter, Buffer and Streams

### EventEmitter, Buffer, Stream — как они связаны

#### Начнём с проблемы, которую они решают
```
Задача: прочитать файл 1GB и отправить клиенту по сети

Наивный подход (без Streams/Buffers/Events):
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│  1. Прочитать ВЕСЬ файл в RAM           → 1GB в памяти      │
│  2. Подождать пока ВЕСЬ прочитается     → блокировка         │
│  3. Отправить ВЕСЬ файл клиенту         → ещё 1GB в буфере  │
│                                                              │
│  Итого: 2GB RAM, программа ждёт, ничего не делает           │
│                                                              │
└──────────────────────────────────────────────────────────────┘

Подход Node.js (EventEmitter + Buffer + Stream):
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│  1. Читаем файл ПОРЦИЕЙ (64KB)       → Buffer (64KB)        │
│  2. Событие 'data' — порция готова    → EventEmitter         │
│  3. Сразу отправляем порцию клиенту   → Stream               │
│  4. Читаем следующую порцию...        → повторяем            │
│                                                              │
│  Итого: 64KB RAM, программа не блокируется                   │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```


### Три концепции — что каждая из них
#### 1. EventEmitter — механизм уведомлений
```
Что: объект который может ГОВОРИТЬ "что-то случилось"
     и другой код может СЛУШАТЬ эти события

Паттерн: Publisher → Event → Subscriber(s)

  emitter.emit('data', payload)     ← "случилось событие data!"
  emitter.on('data', (payload) => { ... })  ← "когда data — сделай это"
```

```
import { EventEmitter } from 'node:events';

const emitter = new EventEmitter();

// Подписка (listener):
emitter.on('order', (item) => {
  console.log(`Получен заказ: ${item}`);
});

// Публикация (emit):
emitter.emit('order', 'pizza');   // "Получен заказ: pizza"
emitter.emit('order', 'burger');  // "Получен заказ: burger"
```

#### 2. Buffer — контейнер для бинарных данных
```
Что: кусок СЫРОЙ памяти фиксированного размера
     для хранения байтов (не строк, не объектов — БАЙТОВ)

Зачем: файлы, сеть, изображения, видео — это всё байты
```

```
// Создание:
const buf = Buffer.from('Hello');
console.log(buf);        // <Buffer 48 65 6c 6c 6f>
                         //         H  e  l  l  o    (в hex)
console.log(buf.length); // 5 bytes

// Buffer — это не строка:
const raw = Buffer.alloc(8);  // 8 байт нулей: <Buffer 00 00 00 00 00 00 00 00>
raw[0] = 0xFF;                // прямой доступ к байту
```

#### 3. Stream — поток данных порциями
```
Что: механизм чтения/записи данных ПОРЦИЯМИ (chunks)
     вместо загрузки всего целиком

Каждая порция — это Buffer.
О каждой порции уведомляет EventEmitter.
```

```
Stream ОБЪЕДИНЯЕТ EventEmitter и Buffer:
  - Stream IS-A EventEmitter (наследует от него)
  - Stream отправляет данные КАК Buffer-ы
  - Stream уведомляет ЧЕРЕЗ события (data, end, error)
```

#### Как они связаны — архитектура
```
═══════════════════════════════════════════════════════════════
                    ИЕРАРХИЯ НАСЛЕДОВАНИЯ
═══════════════════════════════════════════════════════════════

              EventEmitter (базовый класс)
              ┌──────────────────────────┐
              │  .on(event, listener)    │
              │  .emit(event, ...args)   │
              │  .once(event, listener)  │
              │  .removeListener()       │
              └────────────┬─────────────┘
                           │
                           │  extends (наследует)
                           │
                    Stream (абстрактный)
              ┌────────────┴─────────────┐
              │  Readable               │
              │  Writable               │
              │  Duplex (оба)           │
              │  Transform (Duplex +    │
              │    модификация данных)   │
              └──────────────────────────┘
              
              Каждый Stream — это EventEmitter.
              stream.on('data', ...) работает потому что
              Stream НАСЛЕДУЕТ .on() от EventEmitter.
```


#### Что передаётся внутри Stream
```
═══════════════════════════════════════════════════════════════
                   ДАННЫЕ ВНУТРИ STREAM
═══════════════════════════════════════════════════════════════

Файл на диске (1GB):
[██████████████████████████████████████████████████████████████]

Stream читает ПОРЦИЯМИ:
[████]  [████]  [████]  [████]  [████]  [████]  ...
  ↓       ↓       ↓       ↓       ↓       ↓
Buffer  Buffer  Buffer  Buffer  Buffer  Buffer
64KB    64KB    64KB    64KB    64KB    64KB

Каждый Buffer доставляется через EVENT:
  emit('data', buffer1)
  emit('data', buffer2)
  emit('data', buffer3)
  ...
  emit('end')
```

#### Полная модель — как всё работает вместе
```
═══════════════════════════════════════════════════════════════
         ЧТЕНИЕ ФАЙЛА — ВСЕ ТРИ КОНЦЕПЦИИ В ДЕЙСТВИИ
═══════════════════════════════════════════════════════════════

fs.createReadStream('video.mp4')

         ДИСК                    STREAM                    ТВОЙ КОД
         ─────                   ──────                    ────────
          │                        │                          │
Время 1:  │ ── читает 64KB ──→    │                          │
          │                        │ Buffer <64KB>            │
          │                        │ emit('data', buf) ──→    │ on('data', callback)
          │                        │                          │ обработал порцию
          │                        │                          │
Время 2:  │ ── читает 64KB ──→    │                          │
          │                        │ Buffer <64KB>            │
          │                        │ emit('data', buf) ──→    │ on('data', callback)
          │                        │                          │ обработал порцию
          │                        │                          │
Время 3:  │ ── читает 64KB ──→    │                          │
          │                        │ Buffer <64KB>            │
          │                        │ emit('data', buf) ──→    │ on('data', callback)
          │                        │                          │ обработал порцию
          │                        │                          │
Время N:  │ ── конец файла ──→    │                          │
          │                        │ emit('end') ────────→    │ on('end', callback)
          │                        │                          │ "готово"
          │                        │                          │
Ошибка:   │ ── диск отвалился →   │                          │
          │                        │ emit('error', err) ──→   │ on('error', callback)
          │                        │                          │ обработал ошибку


РОЛИ:
  Buffer:        ЧТО передаётся (контейнер с байтами)
  EventEmitter:  КАК уведомляется (механизм событий)
  Stream:        КОГДА и ОТКУДА (логика чтения порциями)
```

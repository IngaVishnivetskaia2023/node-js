#### What middleware actually is:

```
Middleware is a function that sits BETWEEN the incoming request
and your final route handler. It has access to req, res, and next.

  The simplest possible middleware:

    function myMiddleware(req, res, next) {
      // do something with req or res
      next();  // pass control to the next middleware
    }

  That's it. Every middleware is just this function signature.


  MENTAL MODEL — the assembly line:

    Raw HTTP request arrives
         │
         ▼
    ┌─────────────┐
    │ Middleware 1│  logging
    └──────┬──────┘
           │ next()
           ▼
    ┌─────────────┐
    │ Middleware 2│  parse JSON body
    └──────┬──────┘
           │ next()
           ▼
    ┌─────────────┐
    │ Middleware 3│  check auth token
    └──────┬──────┘
           │ next()
           ▼
    ┌─────────────┐
    │Route Handler│  your business logic
    └──────┬──────┘
           │ res.json()
           ▼
    Response sent to client

    Each station on the assembly line:
      - Inspects the request
      - Optionally modifies it
      - Either passes it along (next) or stops it (res.send)
```


#### How Express builds on raw http

```
// Express is literally this under the hood:

import http from 'http';

const app = express();

// When you call app.listen(3000):
// Express does exactly this:
http.createServer(app).listen(3000);
//                 ^^^
//                 app IS the callback function
//                 app IS (req, res) => { ... }

// Express enhances the raw req and res objects:
//   req gets: req.body, req.params, req.query, req.cookies, etc.
//   res gets: res.json(), res.send(), res.redirect(), res.status(), etc.
//
// Then Express runs your middleware chain with these enhanced objects.
```

```
  Raw http module:

    http.createServer((req, res) => {
      // ONE function handles EVERYTHING
      // routing, body parsing, auth, business logic
      // all crammed in here
    });


  Express:

    app.use(cors());                     // middleware 1
    app.use(express.json());             // middleware 2
    app.use(authenticate);               // middleware 3
    app.get('/api/users', getUsers);     // route handler
    app.post('/api/users', createUser);  // route handler
    app.use(errorHandler);               // error middleware

    // Express splits that ONE function into a chain of
    // small, focused, reusable functions.
    // Each does one thing. Runs in order. Passes control via next().
```

#### The middleware stack — what Express maintains internally

```
Every time you call app.use() or app.get(), Express pushes
an entry onto an internal STACK (array):

  app.use(cors());
  app.use(express.json());
  app.use(authenticate);
  app.get('/api/users', getUsers);
  app.post('/api/users', createUser);
  app.use(errorHandler);


  Express internal stack (simplified):

  [
    { path: '/',           method: ALL,  fn: cors()         },
    { path: '/',           method: ALL,  fn: express.json() },
    { path: '/',           method: ALL,  fn: authenticate   },
    { path: '/api/users',  method: GET,  fn: getUsers       },
    { path: '/api/users',  method: POST, fn: createUser     },
    { path: '/',           method: ALL,  fn: errorHandler   },
  ]

  app.use()  → method: ALL, matches any HTTP method
  app.get()  → method: GET only
  app.post() → method: POST only

  app.use()  without path → path: '/' (matches everything)
  app.use('/api') → path: '/api' (matches /api and /api/*)


  When a request arrives:
    Express walks the stack TOP TO BOTTOM.
    For each entry: does path match? Does method match?
    YES → run the function.
    NO  → skip, check next entry.
```

#### How `next()` works internally

```
// Simplified version of what Express does internally:

function handleRequest(req, res) {
  const stack = app._stack;  // array of middleware entries
  let index = 0;

  function next(err) {
    // Find the next matching middleware
    while (index < stack.length) {
      const layer = stack[index];
      index++;

      // Does this layer match the request?
      if (!matchPath(layer.path, req.url)) continue;
      if (layer.method !== 'ALL' && layer.method !== req.method) continue;

      // Is this an error handler? (4 params)
      if (layer.fn.length === 4) {
        // Only call error handlers if there IS an error
        if (err) {
          layer.fn(err, req, res, next);
          return;
        }
        continue;  // skip error handlers when no error
      }

      // Normal middleware (3 params)
      if (err) continue;  // skip normal middleware when there's an error

      // RUN this middleware
      try {
        layer.fn(req, res, next);
      } catch (e) {
        next(e);  // catch sync errors, pass to error handlers
      }
      return;
    }

    // No more middleware. If error, send 500. If no match, send 404.
    if (err) {
      res.status(500).json({ error: 'Internal Server Error' });
    } else {
      res.status(404).json({ error: 'Not Found' });
    }
  }

  // Start the chain
  next();
}
```

```

WHAT next() DOES:

  next()         →  "I'm done. Run the next middleware."
  next(error)    →  "Something broke. Skip to error handler."
  (not calling)  →  "Chain stops here. I'll send the response."


  VISUAL — the call chain:

  Request: POST /api/users { name: "Anna" }

  Express starts → next()
    │
    │  cors() middleware
    │    matches: path '/' ✅, method ALL ✅
    │    adds CORS headers to res
    │    calls next()
    │        │
    │        │  express.json() middleware
    │        │    matches: path '/' ✅, method ALL ✅
    │        │    reads req body chunks (data + end events)
    │        │    JSON.parse → puts on req.body
    │        │    calls next()
    │        │        │
    │        │        │  authenticate middleware
    │        │        │    matches: path '/' ✅, method ALL ✅
    │        │        │    reads Authorization header
    │        │        │    validates JWT → puts user on req.user
    │        │        │    calls next()
    │        │        │        │
    │        │        │        │  getUsers handler
    │        │        │        │    matches: path '/api/users' ✅
    │        │        │        │    BUT method GET ≠ POST ❌
    │        │        │        │    SKIP
    │        │        │        │
    │        │        │        │  createUser handler
    │        │        │        │    matches: path '/api/users' ✅
    │        │        │        │    method POST ✅
    │        │        │        │    runs handler
    │        │        │        │    res.status(201).json(newUser)
    │        │        │        │    DOES NOT call next()
    │        │        │        │    response sent ✅
    │        │        │        │
    │        │        │        └── chain stops here
    │        │        └────────
    │        └─────────────────
    └──────────────────────────
```


#### The three things middleware can do

```
Every middleware has exactly THREE choices:

  1. MODIFY req/res and pass along
  ─────────────────────────────────

    function addRequestTimestamp(req, res, next) {
      req.startTime = Date.now();          // mutate req
      res.set('X-Request-Id', uuid());     // mutate res
      next();                               // pass along
    }
    
    Later middleware / route handler can read req.startTime.
    This is how data flows FORWARD through the chain.


  2. END the request (send response)
  ──────────────────────────────────

    function requireAuth(req, res, next) {
      const token = req.headers.authorization;
      
      if (!token) {
        res.status(401).json({ error: 'No token provided' });
        // NO next() call. Chain STOPS.
        // Response sent. Done.
        return;
      }
      
      req.user = verifyToken(token);
      next();  // token valid, continue chain
    }

    This middleware is a GATE.
    No token → blocked (401). Never reaches route handler.
    Valid token → passes through. Route handler runs.


  3. FORWARD an error
  ───────────────────

    function parseBody(req, res, next) {
      try {
        req.body = JSON.parse(rawBody);
        next();           // success → continue normally
      } catch (err) {
        next(err);        // failure → skip to error handler
      }
    }
    
    next(err) SKIPS all normal middleware.
    Jumps directly to the error handling middleware.
```


#### Mutation — how middleware shares data

```
Middleware communicates by MUTATING the req object.
This is Express's core pattern.

  There is no return value. No parameter passing.
  Just: "I'll put data on req. Next middleware reads it."


  ┌────────────────────────────────────────────────────────────┐
  │                                                            │
  │  express.json() middleware:                                │
  │    reads raw body from stream                             │
  │    parses JSON                                            │
  │    sets req.body = { name: "Anna" }                       │
  │    calls next()                                            │
  │                                                            │
  │  authenticate middleware:                                  │
  │    reads req.headers.authorization                        │
  │    validates JWT                                           │
  │    sets req.user = { id: 123, role: "admin" }             │
  │    calls next()                                            │
  │                                                            │
  │  route handler:                                            │
  │    reads req.body  ← set by express.json()                │
  │    reads req.user  ← set by authenticate                  │
  │    has everything it needs                                 │
  │    res.json({ created: true })                             │
  │                                                            │
  └────────────────────────────────────────────────────────────┘


  req when it enters the chain:
  {
    method: 'POST',
    url: '/api/users',
    headers: { authorization: 'Bearer eyJ...', ... }
    // that's it from raw http
  }

  req when it reaches your route handler:
  {
    method: 'POST',
    url: '/api/users',
    headers: { authorization: 'Bearer eyJ...', ... },
    body: { name: "Anna", age: 30 },           ← express.json()
    user: { id: 123, role: "admin" },           ← authenticate
    startTime: 1705312800000,                   ← timing middleware
    requestId: "abc-123-def",                   ← request ID middleware
    params: { },                                ← Express routing
    query: { },                                 ← Express parsing
    ip: "203.0.113.50",                         ← Express
  }

  Each middleware ENRICHES the request object.
  By the time your handler runs, everything is ready.
```

#### Order matters — deeply

```
// ✅ CORRECT ORDER:

app.use(express.json());        // 1. parse body first
app.use(authenticate);          // 2. then check auth (needs body sometimes)
app.get('/api/users', handler); // 3. then handle request (needs both)


// ❌ WRONG ORDER:

app.use(authenticate);          // 1. check auth
app.use(express.json());        // 2. parse body ← TOO LATE
app.get('/api/users', handler); // 3. handle request

// authenticate tries to read req.body for API key in body
// but express.json() hasn't run yet
// req.body is undefined → auth fails for every request


// ❌ WRONG ORDER:

app.get('/api/users', handler); // 1. handle request
app.use(express.json());        // 2. parse body ← NEVER REACHED
app.use(authenticate);          // 3. check auth ← NEVER REACHED

// handler runs first, sends response
// never calls next()
// express.json() and authenticate never execute


// ❌ WRONG ORDER:

app.use(errorHandler);          // 1. error handler first
app.use(express.json());        // 2. body parser
app.get('/api/users', handler); // 3. route handler

// if handler throws an error, Express looks for error handler
// AFTER the throwing middleware in the stack
// errorHandler is BEFORE it → never catches the error
```

```
THE RULE:

  Top of file:    general middleware (logging, cors, body parsing)
  Middle:         auth middleware, validation
  After that:     route handlers
  Very bottom:    error handling middleware (MUST be last)

  app.use(helmet());              // security headers
  app.use(cors());                // CORS
  app.use(morgan('dev'));         // logging
  app.use(express.json());       // body parsing

  app.use(authenticate);         // auth check

  app.use('/api/users', userRoutes);    // routes
  app.use('/api/search', searchRoutes); // routes

  app.use(notFoundHandler);      // 404 catch-all
  app.use(errorHandler);         // error handler (LAST)
```

#### Error handling middleware — the 4-parameter signature

```
// Normal middleware: 3 parameters
function normalMiddleware(req, res, next) { }

// Error middleware: 4 parameters
function errorMiddleware(err, req, res, next) { }
//                       ^^^
//                       Express checks fn.length === 4
//                       to identify error handlers

// This is NOT a convention. Express literally counts parameters.
// 4 params = error handler. 3 params = normal middleware.
```

```
HOW ERRORS FLOW:

  Normal flow (no errors):

    cors → json → auth → handler → response
    next()  next()  next()  res.json()

  
  Error flow (something breaks):

    cors → json → auth → THROWS ERROR
                           │
                           │ next(err) or uncaught throw
                           │
                           ▼ SKIP all normal middleware
                           │
                           │ skip handler (normal, 3 params)
                           │ skip another middleware (normal, 3 params)
                           │
                           ▼ FIND error middleware (4 params)
                           │
                        errorHandler(err, req, res, next)
                           │
                           ▼
                        res.status(500).json({ error: '...' })
```

```
// Complete error handling pattern:

// Middleware that might fail
function authenticate(req, res, next) {
  try {
    const token = req.headers.authorization?.split(' ')[1];
    
    if (!token) {
      // Create error with status code
      const err = new Error('No token provided');
      err.status = 401;
      return next(err);  // → jumps to error handler
    }
    
    req.user = jwt.verify(token, SECRET);
    next();  // → continues to next middleware
    
  } catch (err) {
    err.status = 401;
    err.message = 'Invalid token';
    next(err);  // → jumps to error handler
  }
}


// Route handler that might fail
app.get('/api/users/:id', async (req, res, next) => {
  try {
    const user = await db.findUser(req.params.id);
    
    if (!user) {
      const err = new Error('User not found');
      err.status = 404;
      return next(err);  // → jumps to error handler
    }
    
    res.json(user);
    
  } catch (err) {
    // Database error, unexpected failure
    next(err);  // → jumps to error handler (will be 500)
  }
});


// Error handler (MUST be last, MUST have 4 params)
function errorHandler(err, req, res, next) {
  
  const status = err.status || 500;
  const message = err.status ? err.message : 'Internal Server Error';
  //              ^^^^^^^^^^
  //              Only show custom message for known errors.
  //              Unknown errors (500) get generic message.
  //              Don't leak stack traces to client.
  
  // Log full error for debugging
  console.error({
    status,
    message: err.message,
    stack: err.stack,
    url: req.originalUrl,
    method: req.method,
    requestId: req.requestId,
  });
  
  // Send clean error to client
  res.status(status).json({
    error: {
      message,
      status,
      ...(process.env.NODE_ENV === 'development' && { 
        stack: err.stack 
      }),
    }
  });
}

app.use(errorHandler);  // LAST middleware
```

app.use((req, res, next) => {

#### Router-level middleware
```
// Create isolated middleware chains with express.Router()

const userRouter = express.Router();

// This middleware only runs for requests hitting this router
userRouter.use((req, res, next) => {
  console.log(`User route: ${req.method} ${req.url}`);
  next();
});

// Param middleware — runs when :id is present
userRouter.param('id', async (req, res, next, id) => {
  // Runs BEFORE the route handler
  // Preloads the user so every handler has it
  try {
    const user = await db.findUser(id);
    if (!user) {
      const err = new Error('User not found');
      err.status = 404;
      return next(err);
    }
    req.foundUser = user;  // attach to req for handlers
    next();
  } catch (err) {
    next(err);
  }
});

userRouter.get('/:id', (req, res) => {
  // req.foundUser is guaranteed to exist here
  // param middleware already validated it
  res.json(req.foundUser);
});

userRouter.put('/:id', (req, res) => {
  // req.foundUser available here too
  // param middleware runs for EVERY route with :id
  res.json({ ...req.foundUser, ...req.body });
});

userRouter.delete('/:id', (req, res) => {
  // same — req.foundUser available
  res.json({ deleted: req.foundUser.id });
});

app.use('/api/users', userRouter);
//       ^^^^^^^^^^^
//       all routes in this router are prefixed with /api/users
//       userRouter.get('/:id') → GET /api/users/:id
```


#### Multiple middleware on single route

```
// You can chain middleware on a single route:

app.post('/api/users',
  
  authenticate,                  // 1. check JWT token
  
  authorize('admin'),            // 2. check role
  
  validateBody(userSchema),      // 3. validate request body
  
  rateLimit({ max: 10 }),        // 4. rate limiting
  
  async (req, res) => {          // 5. handler (only if all above pass)
    const user = await db.createUser(req.body);
    res.status(201).json(user);
  }
);

// Each middleware is a gate.
// If ANY gate fails → chain stops → error response.
// ALL gates pass → handler runs.

// authenticate: no token? → 401, chain stops
// authorize: not admin? → 403, chain stops
// validateBody: invalid data? → 422, chain stops
// rateLimit: too many requests? → 429, chain stops
// handler: only runs if user is authenticated, authorized,
//          has valid data, and isn't rate limited
```


#### How `authorize('admin')` works — middleware factories

```
// authorize is NOT middleware.
// authorize RETURNS middleware.
// It's a function that creates a function.

function authorize(...allowedRoles) {
  // This returned function IS the middleware
  return (req, res, next) => {
    // req.user was set by authenticate middleware earlier
    if (!req.user) {
      const err = new Error('Not authenticated');
      err.status = 401;
      return next(err);
    }
    
    if (!allowedRoles.includes(req.user.role)) {
      const err = new Error('Insufficient permissions');
      err.status = 403;
      return next(err);
    }
    
    next();  // role is allowed, continue
  };
}

// Usage:
app.get('/api/users', authorize('admin', 'manager'), getUsers);
app.delete('/api/users/:id', authorize('admin'), deleteUser);

// authorize('admin') is called at setup time
// returns (req, res, next) => { ... }
// Express stores that returned function in the stack
```

#### Built-in middleware — what they actually do

// express.json()
// ──────────────
// Does what you did manually with raw http:

// Without express.json() — raw http approach:
app.use((req, res, next) => {

#### Async middleware — the gotcha

```
// ❌ BROKEN: async errors are NOT caught by Express

app.get('/api/users', async (req, res, next) => {
  const users = await db.query('SELECT * FROM users');
  // If db.query REJECTS:
  //   Error is thrown inside async function
  //   Express does NOT catch it (Express was built before async/await)
  //   Error becomes unhandled promise rejection
  //   No error response sent to client
  //   Client hangs forever
  res.json(users);
});


// ✅ FIX 1: try/catch in every handler

app.get('/api/users', async (req, res, next) => {
  try {
    const users = await db.query('SELECT * FROM users');
    res.json(users);
  } catch (err) {
    next(err);  // manually forward to error handler
  }
});


// ✅ FIX 2: wrapper function (DRY)

function asyncHandler(fn) {
  return (req, res, next) => {
    // fn returns a promise (async function)
    // if promise rejects, .catch forwards to next(err)
    Promise.resolve(fn(req, res, next)).catch(next);
  };
}

app.get('/api/users', asyncHandler(async (req, res) => {
  const users = await db.query('SELECT * FROM users');
  res.json(users);
  // If this throws, asyncHandler catches it → next(err) → error handler
}));


// ✅ FIX 3: Express 5 handles this natively

// Express 5 (currently in beta) catches async rejections:
app.get('/api/users', async (req, res) => {
  const users = await db.query('SELECT * FROM users');
  res.json(users);
  // Express 5 catches this automatically
  // No wrapper needed
});
```

#### Complete real-world middleware stack

```
import express from 'express';
import helmet from 'helmet';
import cors from 'cors';
import morgan from 'morgan';
import rateLimit from 'express-rate-limit';

const app = express();

// ═══════════════════════════════════════════════
// SECURITY (run first — protect everything below)
// ═══════════════════════════════════════════════

app.use(helmet());
// Sets security headers:
//   X-Content-Type-Options: nosniff
//   X-Frame-Options: DENY
//   Strict-Transport-Security: max-age=31536000
//   Content-Security-Policy: ...
//   etc.

app.use(cors({
  origin: process.env.ALLOWED_ORIGIN,
  credentials: true,
}));
// Handles CORS preflight (OPTIONS) and response headers
// Without this: browser blocks cross-origin requests


// ═══════════════════════════════════════════════
// LOGGING (before body parsing — log even bad requests)
// ═══════════════════════════════════════════════

app.use(morgan('dev'));
// Logs: POST /api/users 201 45ms - 231
//       method url status time - bytes


// ═══════════════════════════════════════════════
// PARSING (before routes — routes need parsed body)
// ═══════════════════════════════════════════════

app.use(express.json({ limit: '10mb' }));
// Parses JSON bodies, rejects if > 10MB

app.use(express.urlencoded({ extended: true }));
// Parses form data


// ═══════════════════════════════════════════════
// REQUEST ENRICHMENT (add metadata to every request)
// ═══════════════════════════════════════════════

app.use((req, res, next) => {
  req.requestId = crypto.randomUUID();
  req.startTime = Date.now();
  
  res.setHeader('X-Request-Id', req.requestId);
  
  res.on('finish', () => {
    const duration = Date.now() - req.startTime;
    if (duration > 1000) {
      console.warn(`SLOW REQUEST: ${req.method} ${req.url} took ${duration}ms`);
    }
  });
  
  next();
});


// ═══════════════════════════════════════════════
// RATE LIMITING (before auth — prevent brute force)
// ═══════════════════════════════════════════════

app.use('/api', rateLimit({
  windowMs: 15 * 60 * 1000,  // 15 minutes
  max: 100,                    // 100 requests per window per IP
  message: { error: 'Too many requests' },
  standardHeaders: true,       // RateLimit-* headers
}));


// ═══════════════════════════════════════════════
// STATIC FILES (before auth — public files need no auth)
// ═══════════════════════════════════════════════

app.use(express.static('public', {
  maxAge: '1y',        // Cache-Control: max-age=31536000
  immutable: true,     // for hashed filenames
}));


// ═══════════════════════════════════════════════
// HEALTH CHECK (before auth — ALB checks this)
// ═══════════════════════════════════════════════

app.get('/health', (req, res) => {
  res.json({ status: 'ok', uptime: process.uptime() });
  // No auth needed. ALB hits this every 30 seconds.
});


// ═══════════════════════════════════════════════
// AUTHENTICATION (after health, before routes)
// ═══════════════════════════════════════════════

app.use('/api', authenticate);
// Everything under /api requires valid JWT
// /health is above this → not protected


// ═══════════════════════════════════════════════
// ROUTES
// ═══════════════════════════════════════════════

app.use('/api/users', userRoutes);
app.use('/api/search', searchRoutes);


// ═══════════════════════════════════════════════
// 404 HANDLER (after all routes — nothing matched)
// ═══════════════════════════════════════════════

app.use((req, res, next) => {
  const err = new Error(`Not Found: ${req.method} ${req.originalUrl}`);
  err.status = 404;
  next(err);  // forward to error handler
});


// ═══════════════════════════════════════════════
// ERROR HANDLER (LAST — catches everything)
// must have 4 parameters, must be last
// ═══════════════════════════════════════════════

app.use((err, req, res, next) => {
  const status = err.status || 500;
  
  console.error({
    requestId: req.requestId,
    method: req.method,
    url: req.originalUrl,
    status,
    message: err.message,
    stack: status === 500 ? err.stack : undefined,
  });
  
  res.status(status).json({
    error: {
      message: status === 500 ? 'Internal Server Error' : err.message,
      requestId: req.requestId,
    }
  });
});
```


```
WHY THIS ORDER:

  helmet/cors       FIRST  — security applies to everything
  morgan            EARLY  — log even requests that fail later
  express.json()    EARLY  — everything needs parsed body
  requestId         EARLY  — all logs/errors include the ID
  rateLimit         BEFORE auth — prevent brute force attacks
  static files      BEFORE auth — public files need no token
  health check      BEFORE auth — ALB needs unauthenticated access
  authenticate      BEFORE routes — all API routes need auth
  routes            MIDDLE — the actual handlers
  404 handler       AFTER routes — nothing matched
  error handler     LAST   — catches errors from everything above
```

## Summary

```
┌──────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  MIDDLEWARE IS:                                                      │
│    function(req, res, next) that sits between request and response   │
│                                                                      │
│  THREE CHOICES:                                                      │
│    next()      → pass to next middleware                             │
│    next(err)   → skip to error handler                               │
│    res.send()  → end the chain, send response                        │
│                                                                      │
│  DATA SHARING:                                                       │
│    Middleware mutates req: req.body, req.user, req.requestId         │
│    Each middleware enriches req for the next one                     │
│                                                                      │
│  ORDER MATTERS:                                                      │
│    security → logging → parsing → auth → routes → 404 → errors       │
│    Each layer depends on what came before it                         │
│                                                                      │
│  ERROR HANDLING:                                                     │
│    4-parameter function: (err, req, res, next)                       │
│    Express counts parameters to identify error handlers              │
│    Must be LAST in the stack                                         │
│    next(err) skips all normal middleware, finds error handlers       │
│                                                                      │
│  ASYNC GOTCHA:                                                       │
│    Express 4 doesn't catch async rejections                          │
│    Wrap with try/catch or asyncHandler wrapper                       │
│    Express 5 fixes this natively                                     │
│                                                                      │
│  MENTAL MODEL:                                                       │
│    Assembly line: each station does one job                          │
│    Gates: each middleware can block or allow the request             │
│    Pipeline: req gets enriched as it flows through                   │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

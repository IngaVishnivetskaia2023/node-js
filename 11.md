## Testing

### Notes for jest

`jest.spyOn()` lets you keep an eye on a real function — see if/how it was called — 
while still letting it do its normal job, UNLESS you explicitly override it with `mockImplementation()`. 
It's the middle ground between "don't touch anything" (no spy) 
and "replace it entirely" (`jest.fn()`/`jest.mock()`) — perfect for when you need to verify behavior without losing the real logic.

```
┌────────────────────────────────────────------------─────┐
│  jest.fn()          → creates a FAKE function from      │
│                         SCRATCH (no real implementation)│
├─────────────────────────────────────------------────────┤
│  jest.mock()           → replaces an ENTIRE MODULE with │
│                            fake versions of everything  │
├───────────────────────────────────────------------──────┤
│  jest.spyOn()   - → wraps a REAL, EXISTING function     │
│                   -  — keeps it working, but lets       │
│                     - you OBSERVE or OVERRIDE it        │
└───────────────────────────────────────------------──────┘
```

#### Basic Usage — Just "Watching" (Original Behavior Kept)
```
const utils = {
  getGenderByName: (name) => {
    return name === 'Alice' ? 'female' : 'male';
  },
};

test('spy just watches, original still runs', () => {
  const spy = jest.spyOn(utils, 'getGenderByName');

  const result = utils.getGenderByName('Alice');

  expect(result).toBe('female');           // ✅ REAL logic still ran
  expect(spy).toHaveBeenCalled();           // ✅ but we ALSO know it was called
  expect(spy).toHaveBeenCalledWith('Alice'); // ✅ and with WHAT arguments
});
```

#### Mental Model:
```
Function call ──► [SPY camera watching] ──► REAL function executes
                          │
                          ▼
                  records: "was called, with these args,
                            returned this value"
```

#### Overriding the Implementation (Temporarily Faking It)
```
test('spy can fake the implementation too', () => {
  const spy = jest.spyOn(utils, 'getGenderByName')
    .mockImplementation(() => 'unknown'); // override just for this test

  const result = utils.getGenderByName('Alice');

  expect(result).toBe('unknown'); // fake value returned, NOT real logic
  
  spy.mockRestore(); // ✅ put the ORIGINAL function back
});
```

#### Mental Model — Why `mockRestore()` Matters:

```
Before spyOn:    utils.getGenderByName → REAL function
After spyOn:      utils.getGenderByName → SPY (maybe faked)
After mockRestore: utils.getGenderByName → REAL function AGAIN

Without restoring, the fake behavior would LEAK into
OTHER tests that run after this one — causing confusing bugs.
```

#### Why Use a Spy Instead of a Full Mock?

```
┌─────────────────────────────────────────--────┐
│  Use jest.fn() / full mock WHEN:              │
│  You don't care about the REAL implementation │
│  at all — you just need a fake stand-in       │
├────────────────────────────────────────────--─┤
│  Use jest.spyOn() WHEN:                       │
│  You WANT the real logic to run (most of the time),│
│  but ALSO want to verify it was called correctly,  │
│  OR occasionally override it for ONE specific test │
└-------─────────────────────────────────────────────┘

```


#### Example:
```
// Verifying a function calls console.error correctly, WITHOUT
// actually printing errors to the test output
test('logs error when input is invalid', () => {
  const consoleSpy = jest.spyOn(console, 'error').mockImplementation(() => {});

  validateInput(null); // this internally calls console.error(...)

  expect(consoleSpy).toHaveBeenCalledWith('Invalid input');

  consoleSpy.mockRestore();
});
```
Why this is a great use case: You want to confirm `console.error` WAS called with the right message, 
but you DON'T want the actual error message cluttering your test output — `spy` + `mockImplementation(() => {})` silences it while still tracking the call.

#### Common Pattern — Restore After Every Test
```
afterEach(() => {
  jest.restoreAllMocks(); // cleans up ALL spies automatically
});
```
